Проверь API контракты: $ARGUMENTS

## Правила
- **НЕ редактируй файлы без одобрения** — сначала покажи что нашёл и план исправлений
- Проверяй и входящие (от клиентов) и исходящие (к внешним API) данные
- Конкретные файлы и строки для каждой проблемы
- Стек определяй по go.mod / package.json; ниже паттерны для Go-бэкенда и React-фронта — основной стек

## Шаг 1: Обнаружение API интеграций

Найди все точки интеграции:

### Входящие (клиенты → Go-бэкенд)
Grep паттерны:
- Роутеры: `chi.Router`, `gin.Engine`, `echo.New`, `http.HandleFunc`, `mux.Handle`
- Хендлеры: `func.*http.ResponseWriter.*\*http.Request`
- Декодирование: `json.NewDecoder`, `json.Unmarshal`, `c.Bind`, `c.ShouldBind`
- Webhook эндпоинты: `/webhook`, `/callback`

### Исходящие (Go-бэкенд → внешние API)
- `http.Get`, `http.Post`, `http.NewRequest`, `http.NewRequestWithContext`, `resty.`
- Кастомные клиенты: `Client{`, `Do(req`
- Фронт: `fetch(`, `axios`, `useQuery`/`useMutation` (React Query)

### Межсервисные
- gRPC: `grpc.Dial`, `.pb.go`, proto-файлы
- Очереди/события: `Publish(`, `Subscribe(`, Watermill-хендлеры — контракт сообщения тоже контракт

## Шаг 2: Аудит валидации

Для каждой найденной интеграции проверь:

### Исходящие запросы (Go)
- [ ] Есть ли `context` с таймаутом (`http.NewRequestWithContext` / `client.Timeout`) — не дефолтный клиент без лимита
- [ ] Проверяется ли `resp.StatusCode` до чтения тела
- [ ] `defer resp.Body.Close()` присутствует
- [ ] Ошибка декодирования обрабатывается (не `_ = json.Unmarshal`)
- [ ] Валидируется ли структура ответа (или слепое обращение к вложенным полям)
- [ ] Обработка rate limit / 5xx / невалидного JSON; retry с backoff для временных сбоев
- [ ] Ошибки оборачиваются с контекстом (`fmt.Errorf("provider X: %w", err)`)

### Входящие запросы (Go)
- [ ] Лимит размера тела (`http.MaxBytesReader`) до декодирования
- [ ] `json.Decoder` с `DisallowUnknownFields()` там, где строгий контракт
- [ ] Валидация DTO после декодирования (validator-теги / ручные проверки обязательных полей)
- [ ] Валидация query/path-параметров (тип, диапазон)
- [ ] Авторизация/аутентификация middleware на приватных роутах
- [ ] Ответ об ошибке не течёт внутренностями (стек, SQL) наружу

### Фронт (React)
- [ ] Ответ бэкенда не используется без проверки (`data?.field`, статусы ошибок React Query)
- [ ] Типы запроса/ответа синхронизированы с бэкендом (сгенерированы, не написаны руками)

## Шаг 3: Карта интеграций

Построй карту по факту находок:
```
[Клиенты]   → REST /api/v1/* (модули: ...)
[Бэкенд]    → Внешний API X (модули: ...)
[Бэкенд]    ⇄ Очередь событий (топики: ...)
[Фронт]     → REST /api/v1/* (хуки: ...)
```

## Шаг 5: Предложение исправлений

Если пользователь хочет исправить — предложи план:

### Быстрые исправления
| # | Файл | Что добавить (таймаут, проверка статуса, MaxBytesReader, DisallowUnknownFields...) |

### Контракт как источник истины (опционально, для системных стыков)
- **OpenAPI-спека** как первичный контракт: для Go — генерация серверных типов/хендлеров (`oapi-codegen`), для React-фронта — генерация клиентских типов из той же спеки
- **JSON Schema** для валидации сообщений очередей/webhook'ов
- Zod-схемы — только на фронте, как производные от OpenAPI, не параллельный рукописный контракт

### Создание валидационных утилит
- Общие хелперы: `decodeJSON[T]` (лимит+strict+валидация), `callAPI` (таймаут+статус+retry)

Дождись одобрения перед внедрением.
