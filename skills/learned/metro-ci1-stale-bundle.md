# Metro с CI=1 отдаёт устаревший бандл (file watching отключён)

**Extracted:** 2026-07-10
**Context:** React Native / Expo — изменения кода «не доезжают» до устройства, хотя Metro запущен и QR сканируется заново.

## Problem
Запуск `CI=1 npx expo start` (или любой запуск Metro с переменной `CI=1`) отключает file watching. Metro продолжает отдавать закэшированный бандл: правки в коде не попадают на устройство ни при Fast Refresh, ни при полной перезагрузке приложения (потрясти телефон → Reload не помогает). Симптом коварный — сервер «работает», ошибок нет.

## Solution
1. Убить Metro и перезапустить БЕЗ `CI=1`, со сбросом кэша:
   ```bash
   npx expo start --clear
   ```
2. `CI=1` допустим только для одноразовых неинтерактивных запусков (CI-сборка), никогда — для live-разработки с устройством.

## Диагностика (как подтвердить именно эту причину)
- Размер отдаваемого бандла **байт-в-байт одинаковый** после заведомых правок кода — значит, перекомпиляции нет.
- Прямая проверка содержимого сервируемого бандла на конкретную строку:
  ```bash
  curl -s "http://<ip>:8081/index.bundle?platform=ios" | grep "уникальная-строка-из-правки"
  ```
  Если строки нет — Metro отдаёт старьё.

## When to Use
- «Я всё перезагрузил, но вижу старую версию» при работе с Expo/Metro.
- Изменения в коде не появляются на устройстве, при этом Metro без ошибок.
- Перед диагностикой «сломанного Fast Refresh» — первым делом проверить, не запущен ли Metro с `CI=1`.
