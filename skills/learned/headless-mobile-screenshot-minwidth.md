# Headless-браузер врёт про мобильную ширину скриншотов

**Extracted:** 2026-08-03
**Context:** Верификация адаптивной вёрстки лендинга скриншотами `msedge --headless=new --screenshot` на Windows.

## Problem

Два подводных камня headless Edge/Chrome при скриншот-проверке вёрстки:

1. **Минимальная ширина окна.** `--window-size=390,H` не даёт реальные 390px: движок клампит окно до ~480–500px, страница рендерится шире, а PNG обрезается до запрошенной ширины. Итог: скриншот выглядит как «обрезанная вёрстка» (ложная тревога) И одновременно скрывает реальные переполнения на 320–470px (ложное спокойствие). На лендинге СпецТехЛизинг так пропустилось переполнение шапки на 360–390px — его нашла только ручная арифметика ширин.

2. **Скриншот молча не записывается.** Без `--virtual-time-budget` файл скриншота периодически не создаётся вовсе (процесс выходит до окончания загрузки), особенно на сетевых URL.

## Solution

- Скриншоты снимать при ширине ≥480px; всё, что уже — проверять расчётом суммы ширин фиксированных элементов (логотип + кнопки + гэпы + паддинги против ширины вьюпорта) или полноценной эмуляцией устройства (chrome-devtools MCP / Playwright с `deviceScaleFactor`).
- Всегда добавлять `--virtual-time-budget=15000 --timeout=30000` и проверять, что файл появился (`Test-Path`), с одним ретраем.

## Example

```powershell
& $edge --headless=new --disable-gpu --virtual-time-budget=15000 --timeout=30000 `
  --window-size=480,3600 --screenshot="$out\shot.png" $url
if (-not (Test-Path "$out\shot.png")) { <# retry once #> }
```

## When to Use

- Любая CLI-проверка адаптивной вёрстки скриншотами headless Edge/Chrome
- Когда «мобильный» скриншот выглядит обрезанным справа — сначала подозревать кламп ширины окна, а не CSS
- Когда файл скриншота не появился без ошибок в выводе
