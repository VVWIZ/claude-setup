# /build: зелёные тесты субагента ≠ рабочее приложение (нет проверки проводки)

**Extracted:** 2026-07-12
**Context:** Оркестрация /build, где фронтенд пишет субагент и отчитывается о зелёных jest+tsc.

## Проблема
Субагент-фронтендер выдал 147/147 jest + tsc 0 ошибок, но на устройстве экран «Книга» бесконечно грузился — забыт вызов `configureBookStore({ api })` (см. [[di-wiring-never-called]]). Юнит-тесты этого не покрывают: они не гоняют интеграцию «экран ↔ стор ↔ api-клиент».

## Урок
Между этапами Frontend и QA-прогоном в /build НЕ хватает шага «аудит проводки / smoke на реальном запуске». Зелёные unit+tsc дают ложную уверенность в работоспособности UI.

## Как применять
- После этапа Frontend — явный шаг: пройти по каждому новому экрану и проверить, что все `configure/subscribe/hydrate/инъекции` реально вызываются из дерева компонентов.
- По возможности — smoke на реальном запуске (лог backend: пошли ли ожидаемые запросы) до вердикта «готово».
- Не принимать «147/147 зелёных» как доказательство работоспособности экрана.

## When to Use
Оркестрация /build, приёмка кода от субагентов, ситуация «тесты зелёные, а вживую не работает».
