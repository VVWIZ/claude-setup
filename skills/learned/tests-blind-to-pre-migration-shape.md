# Тесты слепы к до-миграционной форме данных

**Extracted:** 2026-08-10
**Context:** Любой перенос источника чтения на новое поле/таблицу, которую заполняет
миграция: `object_id` → `members`, одиночное поле → коллекция, денормализация → явная связь.

## Проблема

Совет «готовь состояние ТОЛЬКО штатным путём (через API/импорт/сервис), а не
присваиванием в сторе» — правильный ([[mutation-check-your-own-tests]]). Но после
миграции он **создаёт слепое пятно**: штатный путь уже пишет НОВУЮ форму, поэтому
ни один тест никогда не видит старую. А прод в неё приходит штатно:

* окно между деплоем образа и прогоном миграции (раннбук почти всегда в этом порядке);
* откат образа: старый класс не знает новых ключей и стирает их при перезаписи
  документа ([[rollback-erases-unknown-fields]]);
* записи, которые миграция намеренно пропустила (конфликты, ошибки).

Реальный случай: 509 зелёных тестов, из них десяток прицельно на права. Guard отвода
перебирал новый список состава; на до-миграционных данных список пуст → цикл не
выполняется → guard превращается в no-op, и отведённый пользователь правит объект,
от которого отведён. Ни один тест не покраснел: все строили тему новым API, поэтому
проверяемое условие выполнялось **по другой причине**, чем заявлено.

Четыре слепых судьи нашли это независимо. Сюит — нет.

## Решение

1. Явно завести фикстуру «данные ДО миграции» и прогнать на ней ключевые
   инварианты — доступ, видимость, счётчики:

```python
def _strip_members(store, initiative_id):
    """Привести тему к форме ДО миграции: состав только в legacy-поле."""
    ini = store.initiatives.get(UUID(initiative_id))
    ini.members = []          # новое поле пусто, старое на месте
    return ini
```

   Это НЕ противоречит правилу «не выдумывай состояние»: состояние реальное,
   система приходит в него сама — просто не через тот путь, которым его строит тест.

2. Пока старое поле физически существует, читать **объединение** (`new ∪ old`) в
   одном хелпере, помеченном к удалению вместе с полем. Объединение может только
   добавить элементы, поэтому ни один guard от него не слабеет.
   Подробнее — [[read-source-migration-lifecycle]].

3. Мутация, которой проверяется такой тест: вернуть чтение к одному новому полю.
   Тест на новой форме останется зелёным при любой реализации — он бесполезен.

## Как обнаружить без жюри

Спроси про новое поле три вещи: **кто его заполняет, когда, и что его стирает.**
Если ответ на «когда» — «миграцией, после деплоя», то существует окно, и тест на
это окно обязан быть. Быстрая эвристика: *«если поле сейчас окажется пустым, какой
тест покраснеет?»* Ни один → сюит проверяет только счастливый путь.

## When to Use

- Перевёл читателей с денормализованного поля на явную коллекцию/таблицу.
- Пишу миграцию данных, которая запускается ОТДЕЛЬНО от деплоя образа.
- Обещаю в документе «откат безопасен» — проверь, что тесты видели откатную форму.
- Ревьюер говорит «на проде это выглядит иначе, чем в тестах».
