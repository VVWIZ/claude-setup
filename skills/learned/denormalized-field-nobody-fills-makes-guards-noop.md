# Денормализованное поле, которое никто не заполняет, превращает контроль в no-op

**Extracted:** 2026-08-01
**Context:** Object-scoped авторизация: у дочерней сущности (решение, поручение) есть копия ссылки на владельца-объект, и на ней висит проверка запретов.

## Проблема
У `Decision` было поле `object_id` — денормализованная копия ссылки, которая на самом деле живёт на родителе (`AgendaItem.object_id`). Проверка выглядела корректно:

```python
rid = resolve_object_id(resource, resource_type)   # -> resource.object_id
if resource_type in OBJECT_SCOPED and rid is not None:   # <-- rid всегда None
    if _is_denied(store, principal, rid, action):
        return deny(...)
```

Но `Decision.object_id` не заполнял **ни один** рабочий путь: импорт создавал решение без него, `confirm(...)` вызывался без аргумента `object_id`. Поле всегда `None` → условие `rid is not None` ложно → шаг запретов **пропускался целиком** → решение принималось по роли: «секретарю можно всё».

Итог: отвод по конфликту интересов на решениях **не срабатывал никогда**. Тем же корнем было убито правило детектора конфликтов (`if d.object_id is not None`) и фильтры видимости в списках (`scope.permits(None)` для привилегированной роли возвращает True).

**Почему тесты молчали:** они сами проставляли поле — `store.decisions.get(id).object_id = oid` — то есть создавали состояние, в которое система не приходит. Зелёный тест проверял защиту, которой нет.

## Решение
1. **Диагностика:** `grep` по присваиваниям поля (`\.object_id =`, `object_id=`) — есть ли ХОТЬ ОДИН путь, который его заполняет в проде? Тест не считается.
2. **Резолв по цепочке владения** в единой точке, а не заплатка в каждом эндпоинте:
   ```python
   def resolve_object_id(store, resource, resource_type):
       oid = getattr(resource, "object_id", None)
       if oid is not None or store is None:
           return oid
       # доезд: assignment -> decision -> agenda_item -> object
       ...
   ```
3. **Тест без искусственной подготовки:** состояние должно возникать штатным путём (импорт → привязка вопроса к объекту → отвод), и в тесте стоит явный `assert entity.object_id is None  # как в проде`.
4. Проверить мутацией: убери резолв — тест обязан покраснеть (у нас `link-prior` отдавал 200 вместо 403).

Денормализацию (заполнять копию каскадом) выбирать осторожно: её уже один раз «забыли» заполнить, и дефект прожил незамеченным; копию придётся синхронизировать при перепривязке родителя.

## When to Use
- Пишешь/ревьюишь object-scoped авторизацию, где проверка читает поле дочерней сущности.
- В коде есть `if rid is not None:` вокруг проверки запрета — спроси, когда `rid` бывает не-None.
- `permits(None)` / `scope`-фильтры: посмотри, что возвращается при None для привилегированных ролей (часто fail-open).
- Тест доступа проставляет поле руками — красный флаг. Родня [[di-wiring-never-called]] и [[mutation-check-your-own-tests]].
