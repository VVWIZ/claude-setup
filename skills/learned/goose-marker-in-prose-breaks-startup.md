# Маркер `+goose` в прозаическом комментарии роняет старт сервера

**Extracted:** 2026-07-31
**Context:** Go-проект с миграциями `pressly/goose` (встроены через `//go:embed`, применяются автоматически при старте). Проверено на goose v3.27.2.

## Problem

В комментарий миграции написано пояснение вида:

```sql
-- Прод-заметка: пересоздавать как CREATE INDEX CONCURRENTLY
-- (+goose NO TRANSACTION) — сейчас БД dev-размера.
```

Сервер перестаёт стартовать **вообще**, на любой миграции, с `migrations_failed` → `os.Exit(1)`. Ни `go build`, ни `go vet`, ни `go test ./...` проблему не видят — они миграции не читают.

Причина в `internal/sqlparser/parser.go`: строка считается аннотацией по условию

```go
strings.HasPrefix(strings.TrimSpace(line), "--") && strings.Contains(line, "+goose")
```

то есть **по факту наличия маркера где угодно в строке комментария**. Дальше `extractAnnotation` убирает все `--`, первый `+goose`, тримит — и требует, чтобы остаток был ровно одной из: `Up`, `Down`, `StatementBegin`, `StatementEnd`, `NO TRANSACTION`, `ENVSUB ON`, `ENVSUB OFF` (сравнение через `EqualFold`). Остаток `( NO TRANSACTION) — сейчас БД dev-размера.` в список не попадает → `errInvalidAnnotation` → падает разбор всего файла.

Тот же класс отказов дают: ведущий пробел перед `--` в строке аннотации, два маркера в одной строке, дубль секции `Up`, `Down` раньше `Up`, `StatementBegin` без `StatementEnd`.

## Solution

1. **Не упоминать маркер в прозе.** Писать «под директивой goose NO TRANSACTION», без символа `+`.
2. **Поставить тест-страж** — он ловит весь класс и стоит десяток строк. Экспортированного парсера goose нет (`sqlparser` и `migrationstats` — internal), поэтому правило воспроизводится вручную по исходнику:

```go
// Скан всех встроенных миграций: строки-комментарии с маркером обязаны быть
// валидными аннотациями; плюс наличие Up/Down и парность StatementBegin/End.
for lineNo := 1; sc.Scan(); lineNo++ {
    line := sc.Text()
    if !strings.HasPrefix(strings.TrimSpace(line), "--") || !strings.Contains(line, "+goose") {
        continue
    }
    cmd := strings.TrimSpace(strings.Replace(strings.ReplaceAll(line, "--", ""), "+goose", "", 1))
    // cmd обязан быть одной из supportedAnnotations, иначе t.Errorf
}
```

## Why it matters

Класс отказа асимметричен: цена ошибки — сервер не поднимается ни в одном окружении, а вероятность поймать её статикой нулевая. В проекте могут быть десятки миграций и ноль тестов, которые их читают, — и это нормально до первого такого комментария.

## Generalization

**Любой формат, где маркер ищется подстрокой, а не позиционно, превращает комментарии в исполняемый код.** Тот же паттерн: `// +build` в старом Go, директивы `#pragma`, magic-комментарии в Ruby/Python. Если инструмент сканирует комментарии на подстроку — упоминание его синтаксиса в документации внутри того же файла ломает инструмент. Проверять: «что будет, если написать имя директивы в обычном тексте?»
