# Тест, исход которого решает хранилище, а не код

**Extracted:** 2026-08-12
**Context:** `SELECT DISTINCT ON (car_id) ... ORDER BY car_id, created_at, user_id` — выбор одного владельца из нескольких. Применимо к любому tie-break в SQL и к «берём первый элемент» там, где порядок задаёт не код.

## Problem

Пишешь явный tie-break (`ORDER BY ..., cm.user_id`), заводишь тест «выбор определён» — тест зелёный. Убираешь `user_id` мутацией — **тест всё равно зелёный**, потому что исход решает не сортировка, а первичный ключ `(car_id, user_id)`: индексное сканирование само отдаёт строки в порядке `user_id`.

То есть тест пинит ИСХОД, но не МЕХАНИЗМ. Он выглядит как доказательство определённости, а доказывает лишь текущий план запроса.

Попытки сделать его настоящим проваливаются предсказуемо:
- выровнять `created_at`, чтобы ничья была настоящей, — план не меняется;
- вставить строки в обратном порядке, чтобы «физически первым» лежал не тот, — план всё равно идёт по индексу.

Это НЕ значит, что явный tie-break не нужен: сейчас определённость держится на плане, а план зависит от статистики, версии СУБД и объёма данных. Явная сортировка превращает совпадение в требование.

## Solution

Три шага, в этом порядке:

1. **Проверить мутацией, а не глазами.** Убрать проверяемое условие и прогнать. Зелёный тест после удаления — сигнал, а не победа.
2. **Попробовать сделать тест настоящим**: выровнять то, что даёт ничью; развернуть порядок вставки; проверить, не решает ли исход индекс.
3. **Если не выходит — записать это в тесте прямым текстом.** Не «тест проверяет определённость», а «тест НЕ ловит удаление `cm.user_id`, и вот почему; он ловит смену исхода, если план однажды изменится».

Честный комментарий о границах теста ценнее уверенного, который врёт: следующий человек (или я через месяц) иначе решит, что место покрыто.

## When to Use

- Тест на `ORDER BY` с неуникальным ключом, `DISTINCT ON`, `LIMIT 1`, «первый подходящий».
- Тест на выбор одного из нескольких равноправных объектов (владелец, адрес, конфиг).
- Любой тест, который я собираюсь описать словом «детерминированно».
- Ветка кода, до которой не добраться через обычный вход, — прежде чем объявить её покрытой.
