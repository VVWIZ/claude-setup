# React Native: вложенные модалки — «present while dismissing» на iOS

**Extracted:** 2026-07-19 (Baby Tracker, дропдаун выбора ребёнка → форма добавления)
**Context:** React Native / Expo Go, iOS. Тап в открытом `RNModal` (дропдаун) закрывает его и тут же открывает второй `RNModal` (форма).

## Проблема
Обработчик в одном тике делает:
```tsx
onPress={() => { setOpen(false); setAdding(true); }}
```
Первый `RNModal` (`animationType="fade"`) начинает **анимацию закрытия** (~200 мс), а второй `RNModal` в это же время пытается презентоваться. На iOS нативный презентер не умеет презентовать поверх окна, которое ещё анимированно закрывается → второе окно **молча не появляется** (часто с первого раза, «через раз»). На Android обычно проходит — поэтому баг ловится только на живом iPhone, не в jest/tsc.

## Решение
Убрать наложение анимаций — закрывать нижнюю модалку **мгновенно**:
```tsx
<RNModal transparent visible={open} animationType="none" ...>
```
Тогда `setOpen(false)` размонтирует дропдаун синхронно, без анимации закрытия, и второй модал презентуется в чистое состояние.

Альтернативы, если анимация закрытия нужна:
- открывать второй модал в `onDismiss` первого (после завершения анимации);
- отложить на кадр: `requestAnimationFrame(() => setAdding(true))` / `setTimeout(…, 250)`.

## When to Use
- Любая цепочка «закрыть один `RNModal` → сразу открыть другой» в том же обработчике: дропдаун→форма, меню→диалог подтверждения, шит→шит.
- Ревью RN-кода: `setX(false); setY(true)` рядом, где оба X/Y — модалки → красный флаг под iOS.
- Симптом «на iPhone окно открывается через раз / не с первого тапа», хотя tsc/jest зелёные (баг рантайм-нативный, тестами не ловится — см. [[build-pipeline-wiring-smoke-gap]]).
