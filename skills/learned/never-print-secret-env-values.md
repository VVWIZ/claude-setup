# Никогда не печатать значения секрет-содержащих env-переменных

**Extracted:** 2026-07-29
**Context:** Проверка одной env-переменной (`BOARDMIND_DISABLE_REGISTRATION`) на Railway
через `railway variables` привела к утечке `BOARDMIND_ENCRYPTION_KEY` и части
`BOARDMIND_JWT_SECRET` в транскрипт — потому что вывод CLI это ASCII-таблица
(`║ NAME │ VALUE ║`), а sed-редакция была написана под формат `NAME=VALUE` и не сработала.

## Problem
Нужно узнать ОДИН несекретный факт (задан ли флаг), но команда листинга печатает
ВСЕ переменные, включая секреты. Пост-фильтр (`sed`/`grep` по `KEY=.*`) не срабатывает,
если CLI форматирует вывод иначе (таблица, JSON, выравнивание) → секрет уходит в
контекст/логи, которые нельзя «отозвать».

## Solution
1. **Тянуть только нужный ключ**, а не весь список. Если CLI умеет — запросить одну
   переменную; если нет — направить полный вывод в файл и `grep` по нему ТОЛЬКО нужное имя,
   печатая `есть/нет`, а не значение.
2. **Никогда не полагаться на пост-редакцию значения** в транскрипте: формат вывода
   заранее неизвестен. Значение вообще не должно попадать в stdout.
3. **Мутации секретов — вслепую**: генерировать в подстановке команды, присваивать env
   переменной шелла, передавать в setter, вывод setter'а — в файл, в транскрипт только
   `exit code` + `len` + редактированный статус.

## Example
```bash
# ПЛОХО: печатает все значения, sed-редакция под другой формат не сработает
railway variables --service X | grep -iE "REGISTRATION|JWT" | sed 's/SECRET=.*/SECRET=***/'

# ХОРОШО: полный вывод в файл, в транскрипт — только факт наличия ключа
railway variables --service X >/tmp/v.txt 2>&1
grep -q "DISABLE_REGISTRATION" /tmp/v.txt && echo "флаг задан" || echo "флаг НЕ задан"

# Ротация секрета вслепую:
NEW=$(python -c "import secrets;print(secrets.token_urlsafe(48))")
railway variables --set "JWT_SECRET=$NEW" --service X >/tmp/r.txt 2>&1
echo "exit=$? (значение не показано)"
```

## When to Use
- Любая инспекция env/секретов на проде (Railway, Vercel, Fly, k8s secrets, `.env` на сервере).
- Ротация ключей/токенов/паролей.
- Любой CLI, чей формат вывода заранее не гарантирован (таблицы, box-drawing, выравнивание).

## Follow-up при уже случившейся утечке
Секрет в транскрипте = скомпрометирован. Ротировать: JWT-секрет — тривиально (comma-list,
подождать TTL или экстренно только новый); ключ шифрования — через reencrypt (MultiFernet
old→new). См. [[boardmind-secret-leak-incident]].
