# Привилегированную самрегистрацию — только bootstrap в пустую организацию

**Extracted:** 2026-07-26
**Context:** FastAPI, мультитенантный RBAC (роль+организация в JWT). Публичный `/auth/register`
принимал `role` и `organization_id` из тела → эскалация. Нашло jury-ревью (security-ось).

## Problem
Открытая регистрация с `role`/`organization_id` из тела = **самоэскалация**: любой POST-ит
`/auth/register` с `role: system_admin` (или `corporate_secretary`) и `organization_id`
существующего тенанта → логинится → JWT несёт эту роль/орг → полный обход RBAC и tenant-изоляции
(атакующий сам себя делает админом в ЧУЖОЙ орг с данными). Но просто «запретить привилегированные
роли в самрегистрации» ломает **bootstrap**: первого админа новой орг тоже никак не создать
(нет админа, чтобы создать админа).

## Solution
Разделить два пути и завязать разрешение на «пустая ли организация»:

1. **Публичный `/auth/register`**: привилегированную роль (видит всю память: admin/secretary/
   chairman/auditor) разрешать **только если в целевой орг НЕТ пользователей** (bootstrap первого
   админа). Если пользователи уже есть → **403**. Непривилегированные роли — как обычно.
2. **`POST /users`** (только `_require_admin`): создаёт аккаунты; **организацию берёт ИЗ ТОКЕНА**,
   не из тела → нельзя завести в чужую орг.

```python
if body.role in PRIVILEGED_ROLES:
    org_has_users = any(u.organization_id == body.organization_id for u in store.users.list())
    if org_has_users:
        raise HTTPException(403, "Привилегированную роль в существующей орг назначает админ.")
    # пустая орг → bootstrap первого админа разрешён
```

Атака закрыта: вступить админом в **существующую** (с данными) орг → 403. Bootstrap в новую
пустую орг безвреден (атакующий — админ своей же пустой орг). Первый админ создаётся, остальные —
через admin-create.

## When to Use
- Проектируешь signup/провижининг, где пользователь выбирает роль и/или организацию.
- Мультитенантность + RBAC: любой публичный эндпоинт, принимающий `role`/`org` из тела, — красный флаг.
- **Побочка для тестов:** фикстуры, регистрирующие НЕСКОЛЬКО привилегированных ролей в одной орге,
  надо переводить на паттерн «bootstrap первого админа → остальных создаёт админ (POST /users)»,
  иначе вторая привилегированная самрегистрация ловит 403.
