# Optimistic UI: тогглы — да, смена контекста — никогда

**Extracted:** 2026-07-18 (инсайт пользователя, Baby Tracker)
**Context:** Проектирование мгновенного отклика UI при медленной сети (дев-туннель, но правило универсально).

## Проблема
Предложение «сделаем смену ребёнка optimistic» разбивается о суть: имя в шапке переключится мгновенно, а данные экрана (сон/температура) ещё секунды показывают ПРЕДЫДУЩЕГО ребёнка. Для health-данных это не косметика: пользователь может принять данные одного ребёнка за данные другого. Рассинхрон «шапка говорит одно — экран показывает другое» хуже честной задержки.

## Правило
- **Optimistic БЕЗОПАСЕН**, когда локальное действие пользователя = источник истины: тогглы («заснул», «гуляем»), лайки, чекбоксы. Сервер лишь записывает факт; откат нужен только при ошибке сети.
- **Optimistic НЕВОЗМОЖЕН по сути** при смене контекста (ребёнок, аккаунт, проект, организация): данные нового контекста неоткуда взять мгновенно. Варианты вместо него:
  - **A. Честный лоадер**: заголовок меняется сразу, данные затемняются/скелетон «Переключаю…» до прихода свежих (дёшево, честно).
  - **B. Stale-while-revalidate**: per-контекст кэш последнего известного состояния + тихое фоновое обновление (мгновенно и почти точно, но дороже и с риском секундной устарелости).

## When to Use
Любой запрос «сделай мгновенный отклик» / жалоба на задержку UI: сначала классифицировать действие — «пользователь-истина» (optimistic ок) или «смена контекста» (лоадер/кэш, НЕ optimistic).
