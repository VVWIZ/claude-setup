# Ресайкл Fabric-вью переносит пропы между экземплярами

**Симптом-сигнатура.** Нативный компонент ведёт себя сломанно, но **только при
определённом порядке открытия экранов/полей**. Классика: «A → B» ломает B, а
«B → A → B» работает. Дефект «липкий»: раз возникнув, живёт до перезапуска
приложения и не лечится правками JS.

**Механизм.** Fabric переиспользует нативные вью через пул, который
**глобальный на класс компонента** (не на экран и не на модалку) и работает как
LIFO-стек: `RCTComponentViewRegistry` → `recycledViews.back(); pop_back()`.
Базовый `RCTViewComponentView.prepareForRecycle` сбрасывает `_eventEmitter` и
`_isJSResponder`, но **не `_props`**. Если библиотека не сбросила своё состояние
сама, в пул уходит вью с живым UIKit-объектом и пропами прошлой жизни.

Дальше срабатывает diff: многие компоненты диффят не против переданного
`oldProps`, а против ivar `_props`. Проп, который был у прежнего владельца и
отсутствует у нового, получает **codegen-дефолт** — для чисел это `0`. Для дат
`0` — это 1 января 1970.

**Реальный случай (`@react-native-community/datetimepicker` 8.4.4, iOS).**
Пикер времени монтировался на вью бывшего календаря → `maximumDate` «был → нет»
→ `maximumDate = 1970` → `UIDatePicker` клэмпил всё к этому максимуму: колесо не
прокручивалось и слало `onChange` с метками около эпохи. Отравленная вью
циркулировала в пуле, а diff `0 == 0` больше не срабатывал — отсюда липкость.

## Как отличить от похожих причин

Ложные следы, на которые легко потратить дни (все были пройдены):
- «наложение модалок / гонка презентаций» — тут ни при чём, корень в unmount;
- «асимметрия ограничений у соседних пикеров» — отравить может **любой**
  экземпляр класса в приложении, пул общий, соседство по экрану значения не имеет;
- смена `display`/стиля — не влияет, испорчен сам UIKit-объект;
- переписывание на свой компонент — лечит симптом ценой нового класса проблем.

**Falsifiable-проверка без устройства-догадок:** если пул глобальный, дефект
воспроизведётся **кросс-экранно** — открыть похожий компонент на ДРУГОМ экране,
затем целевой. Сломается, хотя на целевом экране «соседа» не было.

## Диагностика по исходникам (быстрее, чем цикл «собери билд → проверь»)

```bash
# 1. Сбрасывает ли библиотека состояние при ресайкле?
grep -n "prepareForRecycle" -A 6 node_modules/<пакет>/ios/fabric/*.mm
# 2. Отключён ли ресайкл вовсе (это и есть фикс)?
grep -rn "shouldBeRecycled" node_modules/<пакет>/ios/
# 3. Поддерживает ли RN этот флаг?
grep -n "shouldBeRecycled" node_modules/react-native/React/Fabric/Mounting/RCTComponentViewRegistry.mm
# 4. Против чего диффятся пропы — против oldProps или ivar _props?
grep -n "_props" node_modules/<пакет>/ios/fabric/*.mm
```

## Починка

1. **Обновить библиотеку** — многие уже закрыли это через
   `+ (BOOL)shouldBeRecycled { return NO; }` (datetimepicker — в 8.5.1, issue #1026).
   Проверить наличие фикса прямо в `node_modules` после установки.
2. **Закрепить версию от отката**: если Expo SDK пинит более старую, добавить в
   `package.json` → `expo.install.exclude`, иначе `expo install --check` вернёт баг.
3. **patch-package** с теми же тремя строками — если обновление заблокировано.
4. Защиты в JS (игнорировать значения-артефакты, напр. год < 2000) **оставить**:
   они дёшевы и страхуют от рецидива, но лечить ими корень нельзя.

⚠️ Фикс **нативный**: доставляется только новой сборкой, не OTA-апдейтом.
В Expo Go зашита своя версия пакета — там баг останется, проверять только в
своей сборке.
