# Субагент не регистрируется (agent type not found) — дебаг-протокол

**Extracted:** 2026-07-10
**Context:** Кастомные субагенты Claude Code (`~/.claude/agents/*.md` или `.claude/agents/*.md` проекта) не появляются в списке доступных типов Agent-тула.

## Problem

Файл агента создан, но вызов `Agent(subagent_type: ...)` падает с `Agent type 'X' not found`, при этом соседние агенты регистрируются нормально. Ложный след: подозрение на поле `model:` (экзотическая модель), из-за чего реальная причина ищется в неверном месте.

## Solution

Проверять в этом порядке:

1. **YAML frontmatter — первым делом.** Неквотированное двоеточие+пробел внутри значения (`description: ... Read-only: не пишет ...`) ломает парсинг **всего файла** — агент молча отбрасывается при любом значении `model:`. Фикс: обернуть description в двойные кавычки. Быстрая диагностика: сравнить frontmatter нерабочего агента с работающим соседним — искать `: ` внутри значений, а не различия в model.

2. **Реестр агентов обновляется ТОЛЬКО на границе сообщений пользователя.** Тестировать регистрацию сразу после правки файла внутри того же хода бесполезно — будет ложный отрицательный результат даже для валидного файла. После правки нужно новое сообщение пользователя, затем тест-вызов.

3. **Модель можно подавать override-параметром на вызове**: `Agent(subagent_type: X, model: fable)` работает в рантайме независимо от пина во frontmatter (в т.ч. для моделей, которых нет в примерах доков). Это устойчивее к версиям CLI: файл агента держит консервативную модель (`opus`/`sonnet`), а особая модель передаётся на вызове.

## Example

```yaml
# ЛОМАЕТ регистрацию (двоеточие+пробел в неквотированном значении):
description: Системный архитектор. Read-only: не пишет файлы.

# РАБОТАЕТ:
description: "Системный архитектор. Read-only: не пишет файлы."
```

Минимальный тест-вызов регистрации (на следующем ходу после правки):

```
Agent(subagent_type: architect, prompt: "Ответь одной строкой: OK")
```

## When to Use

- Ошибка `Agent type '...' not found` при существующем файле агента
- Новый агент не появился в reminder «New agent types are now available»
- Часть агентов из одной папки регистрируется, часть — нет
- Нужно запустить субагента на модели, которую frontmatter «не принимает»

Подтверждено живыми вызовами 2026-07-10 при установке роутинга моделей (см. память `model-routing-setup`).
