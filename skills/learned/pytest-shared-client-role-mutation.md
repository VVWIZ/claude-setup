# pytest: общий клиент с мутацией роли уводит захваченную ссылку

**Extracted:** 2026-07-21
**Context:** BoardMind `tests/test_api.py`, класс-обёртка `Api` над одним `TestClient`; `api.as_(role)`/`api.sec` переключают `Authorization`-заголовок **одного и того же** клиента и возвращают его.

## Проблема

Тест-хелпер держит ОДИН `TestClient` и на каждом `api.as_(role)` / `api.sec` меняет его
`headers["Authorization"]`, возвращая тот же объект. Если захватить ссылку —
`c = api.sec` — а потом вызвать `api.as_("board_member")`, то `c` **тоже** становится
board_member (это тот же объект). Дальнейший `c.post(...)` уходит под чужой ролью →
неожиданный 403/404, а `.json()` возвращает `{"detail": ...}` → `KeyError` на ожидаемом поле.

Симптом обманчив: изолированный прогон эндпоинта даёт 201, а тест падает с
`KeyError: 'other_object_id'` (или подобным) — потому что ломается не код, а порядок ролей в тесте.

## Решение

Не кэшировать `c = api.sec`. Вызывать `api.sec` / `api.as_(role)` **явно на каждом шаге**,
чтобы заголовок переустанавливался прямо перед запросом:

```python
# ПЛОХО — c уводится последующим переключением роли:
c = api.sec
assert api.as_("board_member").post(url, json=body).status_code == 403
rel = c.post(url, json=body).json()   # c теперь board_member! -> 403 -> KeyError

# ХОРОШО — роль переустанавливается на каждом вызове:
assert api.as_("board_member").post(url, json=body).status_code == 403
rel = api.sec.post(url, json=body).json()   # снова секретарь
```

## When to Use

- Пишешь pytest на FastAPI `TestClient` с обёрткой, которая меняет общий заголовок
  (`api.as_(role)`, `api.sec`, «переключатель токена») и в одном тесте чередуешь роли.
- Симптом: `KeyError`/неожиданный 403-404 в мультиролевом тесте, хотя эндпоинт при
  изолированной проверке отвечает верно → подозревай увод захваченной ссылки на общий клиент.
- Общий признак: хелпер, возвращающий **мутируемый разделяемый объект** (клиент/сессия) —
  не кэшируй его между сменами состояния; бери заново на каждом шаге.
