# Ожидание, выведенное из проверяемой константы, эту константу не пинит

**Extracted:** 2026-08-04
**Context:** Тесты на окна, пороги, лимиты, TTL, «за сколько дней предупредить» — всё, где в коде есть именованная константа, а тест строит вход относительно неё.

## Проблема

Тест выглядел добросовестно: проверял, что напоминание заводится ровно за
`InspectionAgeCreateBeforeDays` дней до срока и не заводится днём раньше.

```go
tooEarly := due.AddDate(0, 0, -(reminders.InspectionAgeCreateBeforeDays + 1))
// → ожидаем 0 напоминаний
edge := due.AddDate(0, 0, -reminders.InspectionAgeCreateBeforeDays)
// → ожидаем 1 напоминание
```

Мутация `30 → 31` тест **не уронила**. И не могла: обе даты сдвинулись вместе
с константой, соотношение сохранилось. Тест пинит только то, что граница
`BETWEEN` **включающая** — реальное свойство, но не то, ради которого его
писали. Значение 30 записано в ТЗ, и уехать оно могло молча.

Это не тот же дефект, что вырожденный тест: здесь проверяется настоящее
поведение, просто не то, которое заявлено именем теста.

## Решение

Разделить два разных утверждения:

1. **Поведение на границе** — можно и нужно считать от константы (иначе тест
   придётся править при каждом изменении значения).
2. **Само значение** — отдельным assert'ом с литералом, со ссылкой на
   документ, где оно зафиксировано.

```go
// Даты ниже выводятся из самих констант, поэтому границу они проверяют, а
// значения — нет. Значения фиксируем отдельно: они записаны в ТЗ 2.5.2.
if reminders.InspectionAgeCreateBeforeDays != 30 ||
	reminders.InspectionAgeNotifyBeforeDays != 15 {
	t.Errorf("правило разошлось с ТЗ 2.5.2: завести за %d, предупредить за %d", ...)
}
```

Ещё лучше, если между константами есть **инвариант** — он ценнее литерала,
потому что объясняет, почему число такое:

```go
// Напоминание обязано существовать раньше, чем о нём придёт время написать.
if reminders.InspectionAgeCreateBeforeDays <= reminders.InspectionAgeNotifyBeforeDays {
	t.Fatal("окно заведения не больше срока предупреждения — сообщение уйдёт с опозданием")
}
```

## Как обнаружить

Только мутацией — см. [[mutation-check-your-own-tests]]. Признак в коде теста:
проверяемая константа встречается **и** в подготовке входа, **и** (неявно) в
ожидании. Если убрать её из ожидания невозможно, потому что ожидание из неё и
состоит — тест самоссылочный.

Быстрая эвристика без прогона: *«если это число завтра станет другим, тест
упадёт?»* Нет → значение не запинено.

## When to Use

- Тест на окно, порог, лимит, TTL, retry-count, «за N дней/км до».
- Константа продублирована в документе (ТЗ, README, миграция) — расхождение
  должно ловиться тестом, а не глазами на ревью.
- Ревьюер говорит «значение запинено слабо» или «любое число в диапазоне
  оставляет тесты зелёными».
