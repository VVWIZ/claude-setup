# Правка файлов питоном на Windows переводит LF → CRLF

**Extracted:** 2026-07-31
**Context:** Class-sweep — механическая замена одного и того же фрагмента в 10+ Go-файлах. Удобнее скриптом, чем десятком точечных правок.

## Problem

Типовой скрипт:

```python
s = pathlib.Path(path).read_text(encoding="utf-8")
s = s.replace(old, new)
pathlib.Path(path).write_text(s, encoding="utf-8")
```

На Windows он молча меняет перевод строки во **всём** файле: `read_text` в текстовом режиме сворачивает `\r\n` → `\n` (universal newlines), а `write_text` разворачивает `\n` → `os.linesep`, то есть обратно в `\r\n`. Если исходники в репозитории на LF (норма для Go), файл целиком становится CRLF.

Проявляется не сразу и не там: `gofmt -l` начинает перечислять файлы, которых не касался форматтер; `gofmt -d` показывает как изменённый **весь файл**; `git diff --stat` вместо «3 строки» показывает «163 строки»; содержательную правку в ревью не разглядеть.

## Solution

Писать байтами с явной нормализацией:

```python
p.write_bytes(s.encode("utf-8").replace(b"\r\n", b"\n"))
```

Либо `open(path, "w", newline="", encoding="utf-8")` — `newline=""` отключает трансляцию.

Если уже испортил — чинится тем же однострочником по списку файлов из `gofmt -l`.

**Проверка после любой скриптовой правки:** `gofmt -l .` (Go) / `git diff --stat` — если число изменённых строк подозрительно велико, смотреть `git diff --ignore-all-space`: если при игнорировании пробелов diff становится нормальным, дело в переводах строк.

## Why it matters

Дефект косметический, но дорогой в момент ревью: содержательная правка class-sweep тонет в шуме, и ни человек, ни слепой судья не смогут проверить, что заменилось именно то, что надо. Плюс hook-и качества (`gofmt`, `prettier`, линтеры) начинают падать на файлах, к которым правка отношения не имела, — и время уходит на поиск не той причины.

## Generalization

**Любой инструмент, читающий и переписывающий файл целиком в текстовом режиме, — потенциальный источник массовой смены переводов строк.** Питон, PowerShell (`Get-Content`/`Set-Content`), Node (`fs.readFileSync` + `toString()` обычно безопасен, но `readline`-обвязки нет). Правило: **для машинной правки исходников работать с байтами, а не с текстом**; и после массовой замены всегда смотреть `--ignore-all-space`-diff как контроль.
