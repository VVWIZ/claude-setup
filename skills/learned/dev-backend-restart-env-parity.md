# Рестарт дев-окружения: сохраняй паритет env

**Extracted:** 2026-07-19 (Baby Tracker, «не удалось добавить фото» после моего рестарта)
**Context:** Ручной перезапуск локального бэкенда/воркеров агентом. Прежний запуск шёл с набором env-переменных (флаги режима), новый — «голой» командой.

## Problem
Поднял бэкенд как `uvicorn app.asgi:app --port 8090` — БЕЗ `DEV_LOCAL_STORAGE=true`, с которым работал прежний инстанс. Настройки (pydantic) → `dev_local_storage=False` → выбирается R2, а bucket не задан → `UnconfiguredStorage` → **тихий `StorageError` 500 на ЛЮБОМ presign/загрузке** (фото книги, документы). Приложение при этом «в целом работает» (auth, чтение) — ломается только подсистема, завязанная на отсутствующий флаг. Ни tsc, ни jest, ни статическое /review этого не видят: это не код, а **операционный слой** (среда запуска).

## Solution
Перед рестартом — узнать, с какими env/флагами шёл прежний процесс, и воспроизвести их:
```bash
# как запущены текущие процессы (Windows/PowerShell):
Get-CimInstance Win32_Process -Filter "Name='python.exe'" | Select CommandLine
# поднимать с тем же окружением:
DEV_LOCAL_STORAGE=true python -m uvicorn app.asgi:app --host 0.0.0.0 --port 8090
```
И ПРОВЕРИТЬ подсистему после старта, а не только `/health`:
```bash
python -c "from app.config import get_settings; print(get_settings().dev_local_storage)"  # ждём True
```
Воркеры, читающие ту же БД/хранилище, поднимать с тем же env.

## When to Use
- Любой ручной рестарт локального сервера/воркеров агентом → сверить env с прежним запуском (не только команду).
- Жалоба «после рестарта перестало работать X», особенно загрузки/интеграции/внешние сервисы — первым делом проверить env-флаги окружения, а не код.
- Общий принцип: зелёные тесты и статическое ревью не покрывают операционный слой (env, миграции применены, процессы живы, порты, хранилище) — проверять отдельно. Пара к [[feedback-verify-runtime-not-green-tests]].
