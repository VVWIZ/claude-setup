# Подпись действия читает то же поле, что и исполнитель

**Extracted:** 2026-08-04
**Context:** Кнопки и предпросмотры вида «Выполнено — напомнить на 194 000 км», «Списать 500 ₸», «Продлить до 1 марта» — всё, где UI обещает конкретный результат до нажатия.

## Проблема

Кнопка считала обещанный срок из интервала **категории**:

```tsx
const target = `через ${cat.suggestRepeatMonths} мес.`;  // 6 для «Резина»
```

А сервер применял интервал **самого напоминания**:

```go
next, _ := reminders.Reminder{RepeatMonths: rm.repeat_months}.NextCycle(...)
// 12 у шаблонов «переобуться на лето» / «на зиму»
```

Кнопка обещала «через 6 мес.», система заводила на 12. Про весеннюю
переобувку не напоминала вообще.

**Ключевое:** 6 и 12 разошлись **законно**. Это разные правила — сезонное
напоминание повторяется раз в год, а от записи о резине до следующей смены
сезона полгода. Сводить константы было бы неправильно. Ошибка не в значениях,
а в том, что подпись читала не тот источник.

Поэтому дефект и не ловится проверкой «нет ли дублирующихся констант»:
дублирования здесь нет, есть два разных справочника с похожими полями.

## Решение

Спросить: **какое поле прочитает исполнитель в момент действия?** Читать
ровно его.

```tsx
// Период берём оттуда же, откуда его возьмёт сервер: у существующего
// напоминания — его собственный, а не интервал категории.
const target = existing
  ? targetText(existing.repeat_months, existing.repeat_km, record.mileage)
  : targetText(cat.suggestRepeatMonths, cat.suggestRepeatKm, record.mileage);
```

Если нужного поля в DTO нет — это и есть настоящая находка: либо добавить его
в ответ, либо не обещать конкретику («Отметить выполненным» без «— напомнить
через N»). Обещание без данных хуже отсутствия обещания.

Родня: не считать на клиенте то, что считает сервер (арифметика месяцев,
округления, налоги) — вторая реализация разойдётся молча. Здесь ровно тот же
корень, только вместо второй реализации — второй источник данных.

## Симптом «ветка создания честная, ветка изменения врёт»

Частый вид: при **создании** объекта UI сам отправляет значение, поэтому
подпись верна; при **изменении** существующего исполнитель берёт значение из
базы, и подпись расходится. Проверять надо обе ветки — первая усыпляет.

## When to Use

- Кнопка/тултип/предпросмотр показывает конкретное число, дату или сумму,
  которую посчитает бэкенд.
- Одно и то же по смыслу значение лежит в двух справочниках (пресеты,
  шаблоны, дефолты категории, настройки объекта).
- Пользователь может отредактировать параметр объекта, а UI берёт исходный
  пресет.
- Ревью говорит «подпись врёт» или «обещали одно, сделали другое».
